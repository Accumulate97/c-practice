## 二、口径与方法（可复现）

1. **两条相似度必须分开看**。掩码相似度把数字/字符串统一掩掉，度量「模板是否相同」；原样相似度保留字面量，度量「题目是否真的一样」。教材原题本身就有成组模板题（如 `c-ch04-fb-011/012/013` 即题4.46/4.47/4.48，只有 a、b、c 取值不同），只看掩码会把它们全误报成「完全相同」——v1 扫描器就踩了这个坑，v2 起修正。
2. 文本特征 = 题干 + 选项，去标点空白后的字符 3-gram；代码特征 = 删 `#include` 行后的 token 4-gram。
3. 综合相似度 = 两侧都有代码时 `0.45 × 文本 + 0.55 × 代码`，否则只看文本。
4. 样板剔除：全局 df > 25% 的 shingle 丢掉（否则所有 C 题都因 `int main`/`printf` 互相「相似」）。本轮剔除实例数：T 19786、Tr 19783、C 7738、Cr 4856。
5. 候选对 = 同题型穷举 + 跨题型倒排索引（只收 df ≤ 20 的稀有 shingle，含原样代码倒排），共 538000 对候选再算精确 Jaccard；尺寸比 < 0.4 的对按 Jaccard 上界直接跳过。
6. **有效性分级以「全库最近邻」为主轴**：一道题在库里最像的那一道，决定了它是「重复占位」还是「新内容」。理由见第三节——母题在数据里不可追溯，按母题分级会把 96% 的变式题判成「无法判定」。

### 3.2 真·雷同 35 对，全部是 AI×AI，且几乎都是「同程序多输入组」

| 子类型 | 对数 | 含义 |
|---|---|---|
| 同程序多输入组（可判分代码相同，只换 stdin） | 32 | `same-code-diff-input` |
| 题干/代码高度雷同但不完全相同 | 3 | `same-text-diff-code` |

「同程序多输入组」= 同一段 C 程序原封不动出成 2–4 道题，只换 stdin（例：`c-ch04-cr-030/031/032` 三题代码完全相同，答案分别是 `Q1\n2` / `6` / `Q4\n8`）。
这类题**答案各不相同、判分没有错**，但学生连做时要把同一段程序读三遍，练习价值远低于题面数量所暗示的水平。
处置建议：合并为一道多输入题（本站 `testCases` 天生支持多组），或把其中 1–2 道改成真正的结构变式。

### 3.3 同模板仅改数值 63 对（AI×AI 50 / 既有×既有 13）

既有×既有 的 13 对是教材原题自带的模板题组（题4.46/4.47/4.48 之类），属正常现象，不建议动。
AI×AI 的 50 对才是「变式只动了数字」的证据，是本轮返工的次优先对象。
