## 五、判分与验证体系

- 后端：Compiler Explorer 公共 API，POST https://godbolt.org/api/compiler/cg132/compile，免 API Key，浏览器直连
- 请求契约：executorRequest: true 与 filters.execute: true 双开关缺一不可；executeParameters 必须位于 options 层级下；编译参数 -std=c99 -Wall -Wextra -O0
- 响应解析：结构扁平、无 execResult 包裹层（禁止 execResult 兜底）；stdout 规范化 (j.stdout||[]).map(o=>o.text).join('\n')；断言 didExecute === true && truncated === false
- 判分顺序：buildResult.code != 0 → compile-error；timedOut → timeout；再看退出码；最后看输出截断。顶层 code = -1 有双重含义（编译失败 / 运行时被信号杀死），必须靠 buildResult 区分
- 超时与并发：软超时 25 s（> Godbolt 自身约 20 s 执行时限，避免两个 20 s 相撞把「运行超时」误判成「后端不可用」）；Godbolt 是排队不是限流且并发越高吞吐越低，故多组测试用例一律严格串行
- 降级模式：后端不可用时读构建期预存 stdout 供学生自评，不计正确率、不置 verified、绝不伪造「通过」
- 抽象层：src/judge/ 的 JudgeBackend，BACKENDS 注册表 + getBackend() + registerBackend()，新增后端按契约补一个适配器即可
- verified 纪律：只允许 npm run judge:verify 实机编译 + 执行 + 比对后置位，禁止手工置 true；verify-data.ts 用 VERIFIED-NO-PROOF 反查报告；后端 5xx / 网络失败判为「未判定」而非「失败」，last_known_good 证据只增不减
- 证据存档 public/data/problems/verification-report.json：2153 次请求 / 总耗时 1182 s / 均值 549 ms / serial_only；1084 道代码题中 1078 道有实机证据，last_known_good 1079 条

## 八、已知缺口

1. 6 道 code_reading 未取得实机证据：c-ch03-cr-017、c-ch03-cr-018、c-ch04-cr-004、c-ch04-cr-011、c-ch04-cr-012、c-ch11-cr-016 —— 这是 verify:data 那 6 条 warn 的唯一来源，也是 verified 停在 2068 的原因（历史遗留，本轮未强改，避免手工置 true 破坏证据纪律）。
2. 主力四型占比 52.3%，低于 AGENTS.md 设定的 80% 目标（存量以选择题/填空为主）。
3. 判分依赖第三方公共服务 godbolt.org，无 SLA；网络受限环境（如本轮遇到的 SNI 过滤）会退到降级模式，只能自评。
4. 进度只存 localStorage：换浏览器/设备不同步，清缓存即丢失（纯静态硬约束下的必然取舍）。
5. 搜索是子串打分，无语义检索、无拼音、无错字纠正。
6. 3D 馆窄屏降级为提示横屏/2D；已限制单演示 ≤200 mesh，但未对 38 个演示逐一做低端 GPU 帧率实测。
7. 全站仅中文，无 i18n。

## 十、本轮踩坑记录（续接者必读）

1. github.com DNS 被 SNI 过滤（只解析到 20.205.243.166，TCP 通但 TLS reset）→ push 必须绕行：
   git -c http.curloptResolve=github.com:443:140.82.113.3 -c http.curloptResolve=github.com:443:140.82.121.3 push origin HEAD
   （失败先用 curl --resolve github.com:443:<ip> https://github.com/ 探测 140.82.112~121 段哪些返回 200）
2. acceptance:online 抽样曾读 p.solution（正确字段是 p.reference）→ 162 道编程题被静默踢出样本池；且固定 seed 的浮点 LCG 溢出 2^53 退化 → 改为 Math.random + 题型分层抽样。
3. 搜索类别 chip 曾拿语料总数冒充命中数（reference 类 0 命中却显示 293 且可点，点完一片空白）→ 改为诚实标 0 并禁用，计数统一走 matchedFiltered 口径。
4. acceptance:learn 的内联 a11y 检查只认 aria-label / textContent，漏了 label[for] → 改为完整 accName 口径计算。
5. 题号直搜（如 c-ch03-pg-001）搜不到 → 打分表加「id 相等 900 / id 子串 140」，结果行用 mark 亮出题号。
6. JudgeLab 的 select 在 375px 撑到 526px → min-w-0 max-w-full。
7. Godbolt 顶层 code = -1 有双重含义（编译失败 / 运行时被信号杀死），必须靠 buildResult 区分，否则会把运行期崩溃误报成编译错误。
8. 验收脚本里「点一下切掉筛选再断言」在 CI 上是竞态：列表重排使按钮移位，click 落空而 Playwright 不报错；固定 waitForTimeout(250) 也盖不住 CI 的慢机器。一律改成「先读 aria-pressed 决定点不点 → 点完 waitForFunction 等到目标计数 → 再断言」。
9. CI runner 已提示 Node 20 弃用（actions/checkout@v4、actions/setup-node@v4 被强制跑在 Node 24 上），目前只是警告。
